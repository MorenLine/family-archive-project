# ВВЕДЕНИЕ

В современном мире сохранение семейной истории и генеалогической информации приобретает всё большую актуальность. С развитием информационных технологий появилась возможность создавать цифровые архивы, которые позволяют не только хранить информацию о членах семьи, но и визуализировать родственные связи, создавая интерактивные генеалогические деревья.

Традиционные методы ведения семейных архивов, такие как бумажные альбомы и рукописные записи, имеют существенные недостатки: они подвержены физическому износу, сложны в поиске информации, не позволяют эффективно визуализировать связи между родственниками и ограничены в возможностях совместного использования несколькими членами семьи.

Разработка веб-приложения для управления семейным архивом позволяет решить эти проблемы, предоставляя пользователям удобный инструмент для систематизации и хранения генеалогической информации с возможностью визуализации семейного дерева, управления фотографиями и биографиями членов семьи.

Целью данной курсовой работы является разработка веб-приложения «Семейный Архив» для управления генеалогической информацией с возможностью визуализации семейного дерева и хранения мультимедийных материалов.

Для достижения поставленной цели необходимо решить следующие задачи:
- провести анализ существующих решений для управления семейными архивами;
- определить функциональные и технические требования к системе;
- спроектировать архитектуру приложения и структуру базы данных;
- реализовать backend-часть приложения на основе Spring Boot;
- разработать frontend-интерфейс с использованием Vue.js;
- обеспечить безопасность данных через систему аутентификации и авторизации;
- реализовать визуализацию генеалогического дерева.

# 1. Постановка задачи и определение основных требований к веб-приложению для управления семейным архивом

## 1.1. Основание для разработки

Необходимость разработки веб-приложения «Семейный Архив» обусловлена возрастающей потребностью в цифровизации генеалогической информации. В настоящее время многие семьи стремятся сохранить историю своих предков, но сталкиваются с трудностями при организации и систематизации такой информации.

Существующие решения на рынке либо имеют ограниченный функционал, либо требуют значительных финансовых затрат, либо не предоставляют достаточной гибкости в настройке под индивидуальные потребности пользователей. Разработка собственного решения позволяет создать специализированный инструмент, учитывающий специфику работы с генеалогическими данными.

## 1.2. Назначение веб-приложения «Семейный Архив»

Веб-приложение «Семейный Архив» предназначено для систематизации, хранения и визуализации генеалогической информации о членах семьи. Приложение позволяет пользователям:

- создавать и редактировать профили членов семьи с указанием персональных данных (имя, фамилия, отчество, даты рождения и смерти, пол, биография);
- устанавливать родственные связи между членами семьи (родители, дети, супруги);
- визуализировать семейное дерево в интерактивном формате;
- загружать и управлять фотографиями, связанными с конкретными персонами;
- просматривать статистику по семейному архиву (общее количество персон, количество поколений, количество фотографий);
- обеспечивать безопасность данных через систему регистрации и аутентификации пользователей.

Приложение ориентировано на широкий круг пользователей, желающих сохранить историю своей семьи в цифровом формате.

## 1.3. Требования к веб-приложению

### 1.3.1. Требования к функциональным характеристикам

Веб-приложение должно обеспечивать выполнение следующих функций:

1. **Управление пользователями:**
   - регистрация новых пользователей;
   - аутентификация пользователей через систему логина и пароля;
   - разграничение прав доступа (обычные пользователи и администраторы);
   - управление профилями пользователей администратором.

2. **Управление персонами:**
   - создание, редактирование и удаление записей о членах семьи;
   - указание персональных данных (ФИО, даты рождения и смерти, пол, биография);
   - установка и изменение родственных связей (родители, дети, супруги);
   - просмотр списка всех персон с возможностью фильтрации;
   - просмотр детальной информации о персоне.

3. **Визуализация семейного дерева:**
   - отображение генеалогического дерева в графическом виде;
   - навигация по дереву с возможностью масштабирования;
   - отображение связей между членами семьи;
   - выделение выбранной персоны в дереве.

4. **Управление фотографиями:**
   - загрузка фотографий для конкретной персоны;
   - просмотр фотографий в галерее;
   - удаление фотографий;
   - указание описания и даты фотографии.

5. **Статистика и аналитика:**
   - отображение общей статистики по архиву (количество персон, поколений, фотографий);
   - подсчёт супружеских пар;
   - анализ структуры семьи.

### 1.3.2. Требования к надёжности

Приложение должно обеспечивать:

- сохранность данных при сбоях системы за счёт использования реляционной базы данных с поддержкой транзакций;
- защиту от потери данных при некорректных операциях через механизм валидации входных данных;
- обработку ошибок с информативными сообщениями для пользователя;
- защиту от циклических ссылок в родственных связях при передаче данных через API.

### 1.3.3. Требования к условиям эксплуатации

Приложение должно работать в следующих условиях:

- операционная система: Windows, Linux, macOS (для сервера);
- веб-браузеры: Google Chrome, Mozilla Firefox, Microsoft Edge, Safari (последние версии);
- разрешение экрана: от 1024x768 пикселей и выше;
- наличие подключения к сети Интернет для доступа к приложению;
- наличие установленной СУБД MySQL версии 8.0 или выше.

### 1.3.4. Требования к составу и параметрам технических средств

Минимальные требования к серверу:

- процессор: 2 ядра, 2 ГГц;
- оперативная память: 4 ГБ;
- свободное место на диске: 10 ГБ;
- сетевой интерфейс: 100 Мбит/с.

Рекомендуемые требования к серверу:

- процессор: 4 ядра, 3 ГГц;
- оперативная память: 8 ГБ;
- свободное место на диске: 50 ГБ;
- сетевой интерфейс: 1 Гбит/с.

### 1.3.5. Требования к информационно-программной совместимости

Приложение должно быть совместимо со следующими программными средствами:

- **Backend:** Java Development Kit (JDK) версии 22 или выше, Spring Boot версии 3.2.4, MySQL Connector/J версии 9.4.0;
- **Frontend:** Vue.js версии 3, Bootstrap версии 5.1.3, библиотека FamilyTree.js для визуализации дерева;
- **База данных:** MySQL версии 8.0 или выше;
- **Сервер приложений:** встроенный сервер Spring Boot (Tomcat) или внешний сервер приложений (Apache Tomcat, Jetty);
- **Протоколы:** HTTP/HTTPS для взаимодействия клиента и сервера, REST API для обмена данными.

# 2. Проектирование программного средства

## 2.1. Разработка модульной структуры программы

Веб-приложение «Семейный Архив» построено по архитектуре клиент-сервер с разделением на backend и frontend компоненты. Backend реализован на основе Spring Boot и следует принципам многослойной архитектуры (layered architecture).

Структура backend-приложения включает следующие основные модули:

1. **Модуль модели данных (model):**
   - `Person` — сущность, представляющая члена семьи;
   - `User` — сущность пользователя системы;
   - `Photo` — сущность фотографии;
   - `Gender` — перечисление для обозначения пола;
   - `Role` — перечисление для обозначения роли пользователя.

2. **Модуль репозиториев (repository):**
   - `PersonRepository` — интерфейс для работы с данными о персонах;
   - `UserRepository` — интерфейс для работы с данными пользователей;
   - `PhotoRepository` — интерфейс для работы с фотографиями.

3. **Модуль сервисов (service):**
   - `PersonService` — бизнес-логика работы с персонами;
   - `UserService` — бизнес-логика работы с пользователями;
   - `PhotoService` — бизнес-логика работы с фотографиями.

4. **Модуль контроллеров (controller):**
   - `PersonApiController` — REST API для работы с персонами;
   - `AuthController` — REST API для аутентификации и регистрации;
   - `PhotoController` — REST API для работы с фотографиями;
   - `AdminController` — REST API для административных функций;
   - `SpaController` — контроллер для обслуживания SPA-приложения.

5. **Модуль безопасности (security):**
   - `SecurityConfig` — конфигурация Spring Security;
   - `JwtTokenProvider` — генерация и валидация JWT токенов;
   - `JwtAuthenticationFilter` — фильтр для проверки JWT токенов;
   - `CustomUserDetailsService` — сервис для загрузки данных пользователя.

6. **Модуль конфигурации (config):**
   - `CorsConfig` — конфигурация CORS для кросс-доменных запросов;
   - `SecurityConfig` — конфигурация безопасности.

7. **Модуль утилит (util):**
   - `SecurityUtil` — утилиты для работы с безопасностью.

Frontend-приложение построено на основе Vue.js 3 и использует компонентный подход. Структура включает:

1. **Компоненты (components):**
   - `HomePage` — главная страница приложения;
   - `Login` — компонент входа в систему;
   - `Register` — компонент регистрации;
   - `PersonList` — список всех персон;
   - `PersonForm` — форма создания/редактирования персоны;
   - `PersonView` — просмотр детальной информации о персоне;
   - `FamilyTree` — визуализация семейного дерева;
   - `AdminPanel` — панель администратора.

2. **Маршрутизация (router):**
   - определение маршрутов приложения;
   - защита маршрутов через проверку аутентификации.

3. **Главный файл приложения (app.js):**
   - инициализация Vue-приложения;
   - настройка глобальных параметров.

## 2.2. Проектирование базы данных

База данных спроектирована с использованием реляционной модели данных. Основные таблицы:

**Таблица `users` (пользователи):**
- `id` (BIGINT, PRIMARY KEY, AUTO_INCREMENT) — уникальный идентификатор пользователя;
- `username` (VARCHAR(255), UNIQUE, NOT NULL) — имя пользователя;
- `email` (VARCHAR(255), NOT NULL) — электронная почта;
- `password` (VARCHAR(255), NOT NULL) — хешированный пароль;
- `role` (VARCHAR(50), NOT NULL, DEFAULT 'USER') — роль пользователя (USER, ADMIN);
- `created_at` (DATETIME) — дата создания записи.

**Таблица `person` (персоны):**
- `id` (BIGINT, PRIMARY KEY, AUTO_INCREMENT) — уникальный идентификатор персоны;
- `first_name` (VARCHAR(255)) — имя;
- `last_name` (VARCHAR(255)) — фамилия;
- `middle_name` (VARCHAR(255)) — отчество;
- `birth_date` (DATE) — дата рождения;
- `death_date` (DATE) — дата смерти;
- `gender` (VARCHAR(20)) — пол (MALE, FEMALE);
- `biography` (TEXT) — биография;
- `parent1_id` (BIGINT, FOREIGN KEY) — ссылка на первого родителя;
- `parent2_id` (BIGINT, FOREIGN KEY) — ссылка на второго родителя;
- `spouse_id` (BIGINT, FOREIGN KEY) — ссылка на супруга;
- `user_id` (BIGINT, FOREIGN KEY, NOT NULL) — ссылка на пользователя-владельца.

**Таблица `photo` (фотографии):**
- `id` (BIGINT, PRIMARY KEY, AUTO_INCREMENT) — уникальный идентификатор фотографии;
- `file_name` (VARCHAR(255), NOT NULL) — имя файла на сервере;
- `original_file_name` (VARCHAR(255)) — оригинальное имя файла;
- `description` (VARCHAR(1000)) — описание фотографии;
- `photo_date` (DATE) — дата фотографии;
- `sort_order` (INT) — порядок сортировки;
- `is_main` (BOOLEAN, DEFAULT FALSE) — флаг главной фотографии;
- `person_id` (BIGINT, FOREIGN KEY, NOT NULL) — ссылка на персону.

Связи между таблицами:
- один пользователь может иметь множество персон (один-ко-многим);
- одна персона может иметь множество фотографий (один-ко-многим);
- персона может иметь двух родителей (многие-к-одному, self-referencing);
- персона может иметь одного супруга (один-к-одному, self-referencing).

## 2.3. Разработка алгоритмов программы

### Алгоритм аутентификации пользователя

1. Пользователь отправляет запрос на `/api/auth/login` с логином и паролем.
2. `AuthController` получает данные и передаёт их в `AuthenticationManager`.
3. `AuthenticationManager` проверяет учётные данные через `CustomUserDetailsService`.
4. При успешной проверке генерируется JWT токен через `JwtTokenProvider`.
5. Токен возвращается клиенту вместе с информацией о пользователе.
6. Клиент сохраняет токен в localStorage и использует его для последующих запросов.

### Алгоритм создания персоны

1. Клиент отправляет POST-запрос на `/api/persons` с данными персоны.
2. `PersonApiController` получает данные и создаёт объект `Person`.
3. Если указаны родители или супруг, выполняется проверка их существования и принадлежности текущему пользователю.
4. Персоне присваивается текущий пользователь как владелец.
5. Объект сохраняется в базу данных через `PersonService`.
6. При установке супруга устанавливается обратная связь.
7. Сохранённая персона возвращается клиенту с очищенными циклическими ссылками.

### Алгоритм построения семейного дерева

1. Клиент запрашивает список всех персон через `/api/persons`.
2. Сервер возвращает список персон с информацией о родителях и супругах.
3. На клиенте выполняется построение графа связей:
   - создаётся карта всех персон по их ID;
   - для каждой персоны устанавливаются связи с родителями и супругом;
   - определяется корневая персона (без родителей) или выбирается произвольная.
4. Используя библиотеку FamilyTree.js, строится визуальное представление дерева.
5. Пользователь может навигировать по дереву, выбирать персон и просматривать детальную информацию.

### Алгоритм удаления персоны

1. Клиент отправляет DELETE-запрос на `/api/persons/{id}`.
2. `PersonService` находит персону и проверяет права доступа.
3. Выполняется обработка связанных данных:
   - у всех детей удаляются ссылки на удаляемого родителя;
   - у супруга удаляется ссылка на удаляемую персону;
   - удаляются все связанные фотографии (через каскадное удаление).
4. Персона удаляется из базы данных.
5. Возвращается подтверждение об успешном удалении.

### Алгоритм загрузки фотографии

1. Клиент отправляет POST-запрос на `/api/photos` с файлом и данными о персоне.
2. `PhotoController` получает файл и сохраняет его в директорию `uploads/photos/` с уникальным именем (UUID).
3. Создаётся объект `Photo` с информацией о файле, описании и дате.
4. Фотография связывается с персоной и сохраняется в базу данных.
5. Возвращается информация о загруженной фотографии.

## 2.4. Описание структур, типов данных и глобальных переменных

### Основные классы модели данных

**Класс `Person`:**
- `id` (Long) — идентификатор персоны;
- `firstName` (String) — имя;
- `lastName` (String) — фамилия;
- `middleName` (String) — отчество;
- `birthDate` (LocalDate) — дата рождения;
- `deathDate` (LocalDate) — дата смерти;
- `gender` (Gender) — пол (enum: MALE, FEMALE);
- `biography` (String) — биография;
- `parent1` (Person) — ссылка на первого родителя;
- `parent2` (Person) — ссылка на второго родителя;
- `spouse` (Person) — ссылка на супруга;
- `childrenOfParent1` (List<Person>) — список детей от первого родителя;
- `childrenOfParent2` (List<Person>) — список детей от второго родителя;
- `photos` (List<Photo>) — список фотографий;
- `user` (User) — владелец записи.

**Класс `User`:**
- `id` (Long) — идентификатор пользователя;
- `username` (String) — имя пользователя;
- `email` (String) — электронная почта;
- `password` (String) — хешированный пароль;
- `role` (Role) — роль (enum: USER, ADMIN);
- `createdAt` (LocalDateTime) — дата создания.

**Класс `Photo`:**
- `id` (Long) — идентификатор фотографии;
- `fileName` (String) — имя файла на сервере;
- `originalFileName` (String) — оригинальное имя файла;
- `description` (String) — описание;
- `photoDate` (LocalDate) — дата фотографии;
- `sortOrder` (Integer) — порядок сортировки;
- `isMain` (Boolean) — флаг главной фотографии;
- `person` (Person) — связанная персона.

### Перечисления (Enums)

**`Gender`:**
- `MALE` — мужской пол;
- `FEMALE` — женский пол.

**`Role`:**
- `USER` — обычный пользователь;
- `ADMIN` — администратор.

### Глобальные конфигурационные параметры

В файле `application.properties` определены следующие параметры:
- `spring.datasource.url` — URL подключения к базе данных MySQL;
- `spring.datasource.username` — имя пользователя БД;
- `spring.datasource.password` — пароль БД;
- `jwt.secret` — секретный ключ для генерации JWT токенов;
- `jwt.expiration` — время жизни токена (86400000 мс = 24 часа);
- `file.upload-dir` — директория для загрузки файлов;
- `spring.servlet.multipart.max-file-size` — максимальный размер загружаемого файла (10 МБ).

## 3.2. Разработка интерфейса взаимодействия пользователя с системой

Пользовательский интерфейс веб-приложения разработан с использованием компонентного подхода Vue.js и адаптивного дизайна Bootstrap. Интерфейс обеспечивает интуитивно понятное взаимодействие пользователя с системой.

### Главная страница

Главная страница (`HomePage`) представляет собой landing-страницу с информацией о приложении. Для неавторизованных пользователей отображаются кнопки входа и регистрации. Для авторизованных пользователей отображается статистика архива (количество персон, поколений, фотографий, супружеских пар) и быстрые действия для перехода к основным разделам приложения.

### Страница входа и регистрации

Компоненты `Login` и `Register` реализуют формы аутентификации. Форма входа содержит поля для имени пользователя и пароля. Форма регистрации дополнительно включает поле электронной почты. После успешной аутентификации JWT токен сохраняется в localStorage браузера и используется для последующих запросов к API.

### Список персон

Компонент `PersonList` отображает таблицу со всеми персонами пользователя. Для каждой персоны отображается полное имя, даты рождения и смерти, пол. Реализована возможность перехода к детальной информации о персоне, редактирования и удаления записей. Предусмотрена кнопка для добавления новой персоны.

### Форма создания/редактирования персоны

Компонент `PersonForm` представляет собой форму с полями для ввода данных о персоне:
- ФИО (имя, фамилия, отчество);
- даты рождения и смерти (с использованием date picker);
- пол (выбор из перечисления);
- биография (многострочное текстовое поле);
- выбор родителей из списка существующих персон;
- выбор супруга из списка существующих персон.

Форма валидирует введённые данные перед отправкой на сервер. При редактировании форма предзаполняется существующими данными.

### Просмотр персоны

Компонент `PersonView` отображает детальную информацию о персоне:
- полное имя и основные данные;
- информацию о родителях с возможностью перехода к их профилям;
- информацию о супруге с возможностью перехода к профилю;
- список детей с возможностью перехода к их профилям;
- галерею фотографий с возможностью просмотра в полноэкранном режиме;
- биографию персоны.

Реализованы кнопки для редактирования, удаления персоны, добавления фотографий и установки супружеских связей.

### Визуализация семейного дерева

Компонент `FamilyTree` использует библиотеку FamilyTree.js для отображения интерактивного генеалогического дерева. Дерево строится на основе данных о персонах и их связях. Реализованы следующие возможности:
- автоматическое построение дерева на основе родственных связей;
- масштабирование и панорамирование дерева;
- выделение выбранной персоны;
- переход к детальной информации о персоне по клику;
- отображение фотографий персон в узлах дерева.

Дерево автоматически определяет корневую персону (без родителей) или позволяет выбрать произвольную персону в качестве корня.

### Панель администратора

Компонент `AdminPanel` доступен только пользователям с ролью ADMIN. Панель отображает список всех зарегистрированных пользователей с возможностью просмотра их архивов и управления правами доступа.

### Навигация и маршрутизация

Маршрутизация реализована через Vue Router с использованием hash-режима для совместимости с различными серверными конфигурациями. Защищённые маршруты проверяют наличие токена в localStorage перед предоставлением доступа. Маршруты приложения:
- `/` — главная страница;
- `/login` — страница входа;
- `/register` — страница регистрации;
- `/persons` — список персон (требует аутентификации);
- `/persons/new` — создание новой персоны (требует аутентификации);
- `/persons/:id` — просмотр персоны (требует аутентификации);
- `/persons/:id/edit` — редактирование персоны (требует аутентификации);
- `/tree` — семейное дерево (требует аутентификации);
- `/admin` — панель администратора (требует роль ADMIN).

### Обработка ошибок

В интерфейсе реализована обработка ошибок при взаимодействии с API:
- отображение информативных сообщений об ошибках пользователю;
- обработка ошибок аутентификации с перенаправлением на страницу входа;
- валидация форм на клиентской стороне перед отправкой данных;
- индикация загрузки данных при выполнении запросов.

Интерфейс разработан с учётом принципов удобства использования (usability) и обеспечивает комфортную работу пользователя с системой на различных устройствах благодаря адаптивному дизайну.
